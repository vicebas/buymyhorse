EquiTag System Concept

Account Creation
When a user creates a HorseRoster account, one permanent EquiTag QR code is generated and assigned. This code never changes, regardless of what it points to.
horseroster.com/eq/A7F2C
Permanent Redirect
The QR code URL is a permanent redirect layer. The destination changes — the code never does. Users can reassign it anytime from their dashboard without reprinting.
→ Horse profile
→ Barn roster
→ Trainer profile
Assignment
From the EquiTag Manager in MyBarn, users assign their QR to any entity they own — a horse, their barn page, or their personal trainer profile. One QR, one destination at a time.
Scan & Discover
Anyone with a phone camera scans the tag. No app needed. They land on a mobile-optimised profile page. If they don't have HorseRoster, they see a smart prompt to join.
URL Architecture

One permanent code. Infinite destinations.

Each EquiTag URL is a two-layer system. The short code (/eq/A7F2C) is permanent and printed. It resolves via server-side redirect to the current assignment. Changing the assignment takes <1 second. The printed tag never needs replacing.

// QR code contains:
horseroster.com/eq/A7F2C
// Redirects to current assignment:
horseroster.com/h/bolt-action-z
// Or reassigned to barn:
horseroster.com/barn/oaklane
Deduplication & Uniqueness

Every code is cryptographically unique.

UUID v4 generation
Codes are generated using UUID v4 at account creation — statistically impossible to duplicate (2¹²² combinations).
Database-level constraint
Unique index enforced at database layer. No two accounts can share a code, even in edge-case race conditions.
One-to-one ownership
A code is permanently bound to one account. It cannot be transferred, sold, or re-issued. Tied to the account UUID in the users table.

Security & Ownership Model

Code Permanence

Once issued, a code is immutable. It cannot be deleted, transferred, or regenerated. The short code is written once at account creation to an append-only log table.

INSERT ONCE · NO UPDATE · NO DELETE
Account Binding

Each QR code is a foreign key to exactly one user account UUID. This relationship is enforced at the database constraint level. No API endpoint allows re-binding to another account.

FOREIGN KEY(account_id) UNIQUE
Abuse Prevention

Scan rate limiting prevents brute-force enumeration of QR codes. Codes use Base-32 with no sequential pattern. A valid scan must also pass a signed token check before redirect.

HMAC-signed · rate-limited · no sequence
Uniqueness Guarantee

UUID v4 generation produces 2¹²² possible codes. The system also checks existing codes at generation time. Collision probability across 1 billion users is ~0.000000006%.

P(collision) at 1B users: ~6×10⁻⁹
Verified Ownership

Only the account owner can reassign their QR destination. All assignment changes require an authenticated session and are 2FA-confirmed for accounts marked "Professional" or "Verified Barn."

auth.session + optional 2FA
Full Audit Log

Every scan, every assignment change, and every download is logged with timestamp, IP, and device. Account owners can view their full scan history and flag suspicious activity.

immutable audit_log table · 90-day retention
