EquiTag QR System — Build new New feature

Generate a QR code for every account at signup

Use the qrcode npm package. The QR encodes the URL horseroster.com/u/[account_id]. Store the short code in the database. Generate SVG + PNG and save both to S3. See §5 and §7 for full code.

npm install qrcode

Add 3 new database tables

equitag_codes (one per account, permanent), equitag_redirects (the current destination, can be updated), equitag_assignment_log (audit trail). Full schema in §5.

Add redirect route: GET /u/:account_id

Looks up the current destination in equitag_redirects and returns a 302 redirect. This is the URL inside the QR code — it must never change. The destination is what changes.

GET /u/:account_id → 302 → current destination

Build the mobile scan landing page: GET /s/:account_id

This is what someone sees when they scan the QR. This page shows a clean preview card of the horse, barn, or trainer profile with a View Full Profile button. No login required. Must be SSR for fast load. Design in §6.

GET /s/:account_id → ScanLandingPage (public, SSR)

Add EquiTag Manager to MyBarn dashboard

A section where the user can view their QR code, download it (SVG and PNG), and assign it to a horse, barn, or trainer profile. Assignment updates the redirect table. Include an assignment history log.

Show EquiTag badge on horse profile + listing cards

If a horse has an EquiTag assigned to it, show the small EquiTag badge on its listing card (bottom-right of photo) and on the full horse profile page.

EquiTag System Flow

Step-by-step logic

How it works — in order

1

User creates a HorseRoster account

2

System generates ONE permanent QR code for that account

This happens automatically at signup. The QR code never changes.

3

QR code points to a permanent URL

horseroster.com/u/{account_id}
4

User chooses what the QR links to

→ A horse profile → A barn page → A trainer page
5

User controls the destination in EquiTag Manager

A section inside the MyBarn dashboard. User can reassign anytime without reprinting the QR.

6

Someone scans the QR — they land on the scan page

horseroster.com/s/{account_id}
7

Scan page shows a preview card with a button

This page shows a clean preview card of the horse, barn, or trainer profile with a View Full Profile button. No login required.

QR Code Generation

Generate automatically at account creation

The QR code should be created the moment a user account is created. It should not require a manual step from the user.

The QR encodes this URL

horseroster.com/u/{account_id}

Example: horseroster.com/u/12345

Save to the user record

The QR image (SVG + PNG) should be saved to the user's record so it can be downloaded from the dashboard and printed on saddle pads or other physical materials.

Package to use

npm install qrcode

Use error correction Level H — the QR lives on saddle pads and will get dirty and worn. Full generation code is in §5.

05

EquiTag — How It Works

New feature to build

Core concept

Each account gets one QR code that points to horseroster.com/u/[account_id]. This URL is printed on physical items and never changes. The user controls what it redirects to from their dashboard. They can point it at a horse, their barn, or their trainer profile — and change it anytime without reprinting anything.

Redirect Flow

horseroster.com/u/acc_12345 → 302 redirect → current destination URL inside the QR code. Never changes.
horseroster.com/u/acc_12345 → horseroster.com/h/bolt-action-z Horse profile
horseroster.com/u/acc_12345 → horseroster.com/barn/oaklane Barn roster
horseroster.com/u/acc_12345 → horseroster.com/trainer/sarah-v Trainer profile

Routes to add

// QR redirect — the permanent URL
GET   /u/:account_id
      → 302 to equitag_redirects.destination_url

// Mobile scan landing page (public, SSR)
GET   /s/:account_id
      → render scan preview page

// Dashboard: update assignment
PATCH /api/equitag/assign
      body: { destination_type, destination_id }

// Dashboard: get QR download URLs
GET   /api/equitag/download
      → { svgUrl, pngUrl }

  changed_at    timestamptz
QR Generation — run at account creation npm install qrcode 
import QRCode from 'qrcode'

async function createEquiTag(accountId: string) {
  const url = `https://horseroster.com/u/${accountId}`

  // SVG — for print, patch manufacturing
  const svg = await QRCode.toString(url, {
    type: 'svg',
    errorCorrectionLevel: 'H', // high — survives embroidery wear
    margin: 4,
    color: { dark: '#0F2A44', light: '#FFFFFF' }
  })

  // PNG — for digital download, business cards
  const png = await QRCode.toBuffer(url, {
    type: 'png', width: 1200, errorCorrectionLevel: 'H', margin: 4
  })

  // Save both to S3
  await Promise.all([
    s3.put(`equitag/${accountId}.svg`, svg, 'image/svg+xml'),
    s3.put(`equitag/${accountId}.png`, png, 'image/png')
  ])

  // Save to database
  await db.equitag_codes.insert({ account_id: accountId })
}

Rule 1

The QR URL never changes

Once generated, /u/{account_id} is permanent. Only the redirect destination changes.

Rule 2

Scan page is always public

The /s/ page requires no login. Anyone with a phone can scan and see it.

Rule 3

One QR per account

One permanent code, created at signup. The user manages it from the EquiTag Manager in their dashboard.
